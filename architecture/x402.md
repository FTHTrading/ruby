# Architecture slice — x402 settlement

**FULL_STACK reference** | Allure Ruby RWA | June 4, 2026

---

## Position in stack

x402 sits in the **operations and settlement** layer — below client-facing Agent Mailor orchestration and beside (not replacing) Legacy Chain anchoring and troptionsmint issuance.

```
[ Investor / Lender ]
        │
        ▼
[ Agent Mailor ] ── KYC / comms / workflow
        │
        ├──► Legacy Vault (VC, BBS+ present, vault manifests)
        │         │
        │         └──► x402 adapter (lib/x402) ──► TROPTIONS gateway ──► USDF settlement
        │
        └──► troptionsmint (Token-2022) ──► transfer hooks (milestone)
```

---

## Boundaries

| Layer | Owns | Does not own |
|-------|------|--------------|
| **ruby (this repo)** | Spec, event schema, hook contracts | Runtime payment processing |
| **Legacy** | BBS+ gate, metered services, Layer 0 hooks | Mint authority |
| **troptionsmint** | SPL mint, on-chain metadata policy | Encrypted certificates |
| **x402 gateway** | HTTP 402, receipt validation, metering | Appraisal / NAV |

---

## RWA event profile

Six event types under `x402-event-v1`: onboarding settlement, revenue share, collateral pledge/release, SPV fee, lifecycle anchor. Sensitive flows require BBS+ presentation via `POST /api/vc/present/bbs` before payment.

---

## Deployment modes

| Mode | Behavior |
|------|----------|
| `LOCAL_ADAPTER` | Dev — mock proofs, no real debit |
| `X402_READY` | Gateway receipt validation enabled |
| `PRODUCTION_REQUIRES_GATEWAY` | Block until gateway configured |

## Valuation

Revenue-share and LTV-dependent logic **blocked** until independent appraisal `completed`. Package described as **target subject to appraisal (TBD)** — not asserted NAV.
